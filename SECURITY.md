# Security Policy

## Supported Versions

Only the latest release is supported: the current `main` branch and the version deployed to production from it. Security fixes are made there. Older commits, forks and self-hosted copies that have not been updated are not supported.

## Reporting a Vulnerability

**Please do not open a public GitHub issue, discussion or pull request for a security vulnerability.** Public reports can put users at risk before a fix is available.

Instead, report it privately by email to **adilurrehmanofficial@gmail.com** with a subject line such as `Security: PDF Merger`.

Please include as much of the following as you can:

- **Reproduction steps** - a clear, step-by-step description (requests, sample files or a proof of concept) that shows the issue
- **Affected component** - for example the merge endpoint, file upload handling, the contact form, security headers, or the deployment configuration
- **Impact** - what an attacker could achieve and under what conditions
- **Suggested fix** - if you have one

Please only test against your own local copy of the project, and do not access, modify or delete other people's data or disrupt the service.

## What to Expect

This is a small, independently maintained project, so there is no fixed response time. Every report is read, and you can expect:

- an acknowledgement once the report has been reviewed
- follow-up questions if more detail is needed
- a note when the issue has been fixed, and credit in the fix if you would like it

Please keep the details private until a fix has been released.

There is no bug bounty or reward program for this project.
